# Muse 아카이브 유지보수·운영 매뉴얼

작성: 2026-10-14. 대상: Archive v2.5.1. 운영자는 Muse, 검증 근거는 실제 브라우저와 저장소 소스입니다.

## 1. 관리 원칙

사용자가 만족했던 v1의 PC·모바일 동작과 크림색/차분한 잉크색 디자인을 기준으로 유지합니다. 변경 완료의 기준은 실제 공개 페이지에서 사용 흐름이 작동하는 것입니다. HTTP 200, node --check, 모의 테스트 결과만으로 완료를 보고하지 않습니다.

- 사용자 원문·이미지·메모·인증정보를 소스 전달 ZIP 또는 공개 문서에 넣지 않습니다.
- v1 루트 index.html은 기준본입니다. 명시적 요청 없이 수정하지 않습니다. 기준 blob: 09c8f6525a8c4409f0d269107afce0e7636d09ea.
- 인쇄, 공유, 이미지 확대, 링크, 번역, 필터, 메모, 북마크, 고정, 복원 기능을 디자인 변경 때문에 없애지 않습니다.
- 확인하지 않은 물리 iPad/iPhone Safari, 카카오톡 수신을 통과했다고 보고하지 않습니다.
- 비밀번호 원문과 OAuth 토큰을 로그·메모리 문서·GitHub·채팅에 기록하지 않습니다.

2. **개인 상태 동기화**: 브라우저의 메모·북마크·고정·삭제 상태를 Drive appDataFolder archive-state.json에 저장. 내려받기는 자동, 내보내기는 매번 비밀번호 확인. 전자는 후자를 우회해서 쓰지 않습니다.

## 3. 개인 상태, 비밀번호, 삭제 복구

Google OAuth scope는 drive.appdata입니다. 토큰은 메모리에만 보관합니다. 연결·재연결·자동 타이머는 GET만 허용합니다. POST/PATCH는 사용자가 관리 메뉴에서 내보내기를 누르고 비밀번호 검증을 통과한 **한 번의 요청**에만 허용합니다. 성공/실패 후 잠금 상태를 유지하고, 실패한 쓰기를 타이머가 자동 재시도하면 안 됩니다.

PIN 비교값만 소스에 있으며 원문은 저장하지 않습니다. 정적 사이트의 PIN은 실수 방지 장치로, 서버 인증을 대신하지 않습니다. PIN 변경·서버 인증 도입은 사용자의 별도 요청에 따라 진행합니다. 이전 버전 탭은 새로고침하지 않으면 이전 동작을 계속하므로 버전 업데이트 안내가 필요합니다.

로컬 저장 키: archive-pinned, archive-bookmarks, archive-bookmark-names, archive-deleted-posts, archive-deleted-replies, archive-removed-replies, archive_memo_*. v1과 호환되는 ID·북마크 색상 스키마를 유지합니다. archive-sync-base는 실제 원격 기준입니다. 내려받기 중에는 로컬 수정이 보존되며 업로드가 발생하지 않습니다.

**삭제 상태도 내보내면 다른 기기에 반영됩니다.** PIN만으로 삭제 내용의 타당성을 판별하지 않습니다. 운영자는 잘못 지운 글을 먼저 ‘보관함 관리 → 숨긴 항목 → 숨긴 글 보기 / 복원’에서 복원하고 정상 상태를 확인한 후 내보내야 합니다. 원본 정본 자료는 삭제되지 않습니다. 댓글 삭제는 아카이브 내 표시 제외이며 원본 X 댓글 삭제가 아닙니다.

복원 전에는 현재 상태를 ‘백업 · 복원 → 저장 데이터 백업’으로 보관합니다. JSON 파일 복원은 확인창 후 진행됩니다. Drive 상태 적용 전 archive-sync-local-backup, 충돌 시 archive-sync-conflicts, 파일 복원 전 archive-before-import가 유지됩니다. 복원 후 모든 기기에서 곧바로 내보내기를 반복하지 말고, 정상 복원한 한 기기의 상태를 기준으로 반영합니다. 로컬 저장소를 일괄 삭제하는 방식으로 해결하지 않습니다.

## 4. 화면과 사용 흐름

- PC 목록: >=1000 CSS px 3열, 768~999px 2열, <768px 1열. 실제 창의 innerWidth를 기록합니다.
- PC 글 클릭: 목록에서 펼쳐 읽기 유지. 펼친 글에도 메모·텍스트 복사·이미지 공유·HTML·인쇄 도구줄 제공. 새 창 버튼을 먼저 누를 필요가 없습니다.
- 모바일: 글 읽기 창, 바깥 탭/Escape 닫기. 이미지 바깥 탭은 글로 복귀.
- 이미지 창: <1000px 이미지 전체 폭, 768~999px에서는 원글 보기/이미지 보기 선택 가능. >=1000px 이미지+400px 원글 패널.
- 글 메뉴: 작은 크림색 면으로 표시, HTML 삼각형 없음. 눌렀을 때 공유/다운로드 선택. 기능 이름을 구현 용어로 더 늘리지 않습니다.
- 목록 기본 아이콘: 같은 20px SVG·32×36 버튼·중립색. 북마크 선택 색으로 내부 채움. 고정핀 빨강, 메모 있는 글은 황금색 면과 점으로 식별.
- 북마크 카드의 좌측과 상단은 선택 색으로 함께 바뀜. 해제하면 기본 테두리로 복귀.
- 북마크 이름 변경: PC 더블클릭/오른쪽 클릭, 터치 긴 누름. 제목 글자를 선택하지 않고 이름 입력란에 포커스·전체 선택. 이동 중 긴 누름 취소.
- 보관함 관리: Drive 동기화 / 백업·복원 / 숨긴 항목. 모바일 세로 구획, PC 가로 구획. 상태 문구가 버튼 사이로 흩어지면 안 됩니다.
- 문단별 번역·원문 링크·관련 글 링크·인용/댓글 이미지·표 테두리를 유지합니다.

## 5. 자동 운영

운영 checkout 경로는 Muse 환경에서 git rev-parse --show-toplevel로 확인합니다. 아래 명령은 해당 checkout 루트에서 실행합니다. Linux 운영용 fcntl/proc 기반 코드이므로 Windows 결과를 실제 운영 검증으로 대체하지 않습니다.

```sh
python3 v2/hooks/launcher.py status
python3 v2/hooks/launcher.py stop
python3 v2/hooks/launcher.py start
```

persistent_worker.py는 작업이 끝난 뒤 300초 대기하며 scheduler_runner.py를 실행합니다. Drive 인제스트 600초, monitor 2400초, 전체 3120초 예산입니다. 워커는 singleton flock/PID로 1개만 유지합니다. launcher status와 실제 프로세스 수를 함께 확인합니다.

운영 로그: v2/hooks/worker.log, scheduler.log (1MB 로테이션). worker는 V2_PUBLISH=1, V2_PUBLISH_BRANCH=main을 자식에 설정합니다. 게시 가드는 현재 checkout 브랜치가 게시 브랜치와 다르면 차단합니다. **review 브랜치나 detached HEAD에서 main에 자동 게시하도록 가드를 우회하지 않습니다.**

기존 12시간 헬스/수신 작업은 유지하고, 중복 agent wakeup 크론은 정지 상태를 유지합니다. 정기 확인을 위해 모델을 5분마다 깨우는 새 작업을 만들지 않습니다. 자료 변경이 없는 주기는 Added 0이며 모델 호출이 없어야 합니다. 번역이 필요한 새 자료만 기존 번역 경로를 사용합니다.

정본: ~/workspace/x-bookmarks/posts.json, ~/workspace/article-archive/index.json, ~/workspace/x-bookmarks/study_links.json, resource_library/index.json, resource_library/ib_juwon.json. 임시 테스트 자료를 이 정본에 섞지 않습니다.

## 6. 자료 갱신 실패 대응

- .retry_media: 이미지 실패/시간 초과. 글 게시는 가능하며 다음 주기에 소스 변경이 없어도 이미지 재시도.
- .retry_translation: 번역 재시도. 번역 상태를 정본 성공 여부와 구분.
- .retry_commit: 커밋/게시 재시도. 네트워크·브랜치·인증 상태부터 확인.
- .monitor_state.json: 후크 성공 후 워터마크 갱신. 실패 후 재시도를 없애려고 해시를 덮어쓰지 않음.
- 이미지 캐시는 확장자 없는 기존 PNG 등을 먼저 확인. URL→media-map→실제 파일의 누락을 비교. 작은 썸네일 대신 원본 우선.
- 마커를 강제로 삭제해 정상이라고 보고하지 않음. 실제 회복 후 코드가 정리해야 함.

## 7. 변경·배포 절차

1. main 상태·정본·로그·변경 파일을 확인하고 영향 범위를 기록합니다. 배포 전 원격 SHA도 기록합니다.
2. 워커를 정상 중지하고 프로세스 0개를 확인합니다. 운영 checkout을 리뷰 브랜치로 바꾼 채 워커를 실행하지 않습니다.
3. 격리 review 브랜치에 소스 변경만 적용. 작업 중인 데이터·미디어·인증 파일을 일괄 add하지 않습니다.
4. 저장소 코드와 실제 브라우저 검증을 완료하고 실패를 수정합니다. 릴리스에 포함되는 경로와 테스트 증거를 기록합니다.
5. index.html의 관련 에셋 쿼리 버전을 모두 함께 올립니다. classic script에 top-level export/import가 있으면 브라우저 전체 파싱이 실패합니다.
6. 승인된 정확한 SHA로 main fast-forward 게시. 원격 main과 SHA/소스 바이트를 대조합니다. force push하지 않습니다.
7. GitHub Pages에서 실제 에셋 버전과 동작이 확인될 때까지 배포 완료라고 말하지 않습니다.
8. main checkout에서 워커 1개 복구, 기존 12h 헬스 유지, 변경 없는 주기와 중복 프로세스/모델 호출 여부 확인.

소스 ZIP은 UTF-8/LF 텍스트만 포함합니다. GitHub 업로드 API를 쓸 경우 base64를 두 번 인코딩하지 않습니다. 반환된 원격 파일 내용과 원본 바이트를 비교합니다.

## 8. 필요한 테스트

```sh
node v2/js/test_integration.mjs
node v2/js/test_bootstrap.mjs
node v2/js/test_drivesync.mjs
node v2/js/test_drive_lifecycle.mjs
python3 -m unittest discover -s v2/hooks -p test_media_mirror.py
```

운영 환경에서는 기존 worker/retry 테스트도 실행하고 실패를 숨기지 않습니다. 기존 retry 테스트 중 review에서 main 푸시를 기대하는 assertion은 현재 게시 가드와 충돌합니다. 그 실패를 고치려고 운영 가드를 없애면 안 됩니다. 기대값 수정은 가드의 정상 동작과 실제 main 재시도를 각각 검증하도록 별도 수행합니다.

브라우저 최소 검사: 320/390/674/768/820/1078/1440 CSS px 및 낮은 가로 화면. 실제 innerWidth, 가로 넘침, 버튼 잘림, 대화창 밖 닫기, PC 펼친 글 도구줄, 터치 긴 누름 입력 포커스, 선택 색/메모/고정 유지 및 해제, 검색/필터 전체 보기, 원문·본문·관련 링크, 이미지 핀치·이동·갤러리, 복사/HTML/공유를 확인합니다.

Drive 테스트는 가짜 계정/상태/테스트 PIN을 격리 fixture에서 사용합니다. 연결·잘못된 PIN·타이머·재연결은 WRITE 0, 올바른 PIN 한 번은 WRITE 1, 다음 타이머는 그대로여야 합니다. 빈 클라우드 생성과 업로드 500 실패 후 로컬 보존/비밀번호 재확인도 검사합니다. 실제 운영 상태에 테스트 메모나 삭제를 올리지 않습니다.

인쇄는 실제 앱이 만든 콘텐츠로 PDF를 생성하고 모든 페이지를 렌더링해 확인합니다. 긴 글의 이미지, 4열 9행 표의 격자, 체크리스트 제목+목록의 페이지 분리, 짧은 글 회색 공백 없음 확인. 합성 1페이지 샘플로 대체하지 않습니다. PC 펼친 글의 인쇄도 반드시 별도로 확인합니다.

## 9. 장애와 롤백

무한 로딩: 브라우저 콘솔 파싱 오류→script 타입/에셋 버전→manifest/data JSON→요청 실패 순서로 확인. HTTP200만으로 정상 판정하지 않음.

잘못된 UI 배포: 워커 중지, 현재 사용자 데이터/정본 보존. 검증된 릴리스의 영향받은 소스 경로만 되돌려 새 커밋으로 배포. index 버전도 변경. git reset --hard, 정본 삭제, force push로 회복하지 않음. 2.5.0(607840da2af65c9614490a28c284224375cd9d32)은 Drive 쓰기 PIN 잠금이 있는 기준본입니다. 더 오래된 전체 버전으로 되돌려 잠금을 제거하지 않음.

개인 상태 오동기화: 정상 기기에서 백업, 숨긴 글 복원/백업 복원, 정상 상태 확인 후 한 번만 내보내기. 원격과 로컬 충돌 사본을 먼저 보존. 브라우저 저장소를 일괄 비우지 않음.

## 10. 운영 인수 체크

Muse는 이 문서를 저장소 v2/docs/MAINTENANCE.md에 보관하고 MEMORY에는 위치·현재 릴리스 SHA·검증 방법·단일 워커와 게시 가드 규칙을 짧게 남깁니다. 문서 내용의 이해와 실제 운영 경로를 확인한 뒤 인수 결과를 보고합니다. 로그에 토큰/사용자 비밀번호를 넣지 않습니다.

향후 보고는 변경 내용, 실제 검증 환경, 공개 릴리스 SHA, 남은 한계를 구분합니다. 미검증인 실제 iOS Safari/카카오톡 수신 및 정적 PIN의 한계를 그대로 명시합니다. 사용자에게 검증을 떠넘기며 완벽하다고 단정하지 않습니다.


## 11. v2.5.2 목록·필터 유지 기준

접힌 카드는 PC 350px, 모바일 340px로 일정하며 제목 2줄·요약 3줄을 미리 보여줍니다. 펼친 글은 자연 높이로 전체 내용을 표시합니다. 저자 핸들은 제목 밖에 두므로 제목 접근성 이름에는 핸들이 포함되지 않습니다. PC에서 글 바깥 클릭은 펼친 글을 접지만, 글 내부 링크·도구 및 대화창에서 발생한 클릭은 접지 않습니다. 메모 창을 닫은 이벤트도 글 바깥 클릭으로 처리하면 안 됩니다.

인물 필터는 많이 모은 저자 3명을 기본 표시하고 우측 전체 인물로 나머지를 펼칩니다. 모든 분류 필터의 게시글 개수는 생략합니다. 인물 스포트라이트는 PC에서 숨기고 모바일의 가로 탐색은 유지합니다. 전체 통계와 검색 결과 개수는 유지합니다. 기본 정렬은 X 숫자 ID에서 발행 시각을 계산하고, 그 외는 date_saved→createdAt→date를 사용하는 기존 혼합 정책을 그대로 유지했습니다.

## 12. 향후 v3: 자료 기반 페르소나 질의응답

현재 v2를 안정화한 뒤 별도 서비스로 도입할 계획이며, 이번 변경에서 질문 서비스나 새 프로젝트를 실행하지 않습니다.

구조: 아카이브 질문 UI → 별도 인증된 Q&A 서버 → 선택한 인물의 자료 검색 → 모델 답변 생성 → 근거 글 링크와 함께 화면에 표시. GitHub Pages는 화면만 제공하고 서버와 비밀 API 키는 별도 환경에서 운영합니다. 응답은 SSE 스트리밍으로 이어서 표시할 수 있으므로 정적 사이트라는 이유로 실시간 답변이 불가능한 것은 아닙니다. 양방향 실시간 음성 등을 붙일 때만 WebSocket 등 별도 통신을 검토합니다. 일반 채팅 프로젝트를 만든 것만으로 외부 호출 가능한 API 서비스가 생기지는 않습니다.

자료는 안정적인 글 ID, 정규화한 저자·별칭, 원문 URL, 발행일·저장일, 본문·번역과 자료 버전을 가진 검색 색인으로 관리합니다. 새 자료 등록 때 색인을 갱신합니다. 기기에서 글을 숨기는 개인 상태를 정본 자료 삭제로 취급하지 않습니다. 인물별 검색 범위를 제한하고, 자료가 부족하면 부족하다고 답하며, 그 사람의 실제 발언과 시스템의 추론을 구분합니다. 답변마다 출처와 해당 게시글을 제시합니다.

도입 순서: ① 별도 저장소·서버에서 읽기 전용 자료 검색 ② 출처가 붙은 기본 Q&A와 품질 평가 ③ 로그인·사용량 제한·비용 한도 ④ 아카이브에 질문 버튼 연결 ⑤ 인물별 말투/관점 설정과 변경 이력 관리. 원문 없는 단정과 출처 불일치를 평가하고, 질문 서비스 장애 시에도 기존 아카이브 열람·검색·메모 기능은 유지합니다. 서버에서 인증과 권한을 검증하며 공개 프런트 코드에 API 키나 운영 비밀번호를 넣지 않습니다. v2의 정적 PIN을 서버 보안 수단으로 재사용하지 않습니다.

참고: https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages · https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events


## 13. v2.5.3 표시 단순화와 로컬 이미지 공유

일반 카드에서 X/웹 출처 배지는 생략하며 필터는 아카이브/IB 주원만 구분합니다. 출처 URL·저자·날짜·주제 및 원문 링크는 유지합니다. 메모 존재는 기존 금색 메모 아이콘으로만 표시하고 추가 점은 표시하지 않습니다.

로컬 검토 HTTP 서버는 .jpg/.jpeg=image/jpeg, .png=image/png, .webp=image/webp, .gif=image/gif로 응답해야 합니다. 잘못된 application/octet-stream은 브라우저에서 그림이 보이더라도 공유 Blob 검증에서 실패합니다. 문제 재현 글은 tweetId 2108875238796583045 (AmeetRai)이며 본문 자체는 이미지가 없고 댓글에 JPG 1개가 있습니다. 전체 글 공유에 포함되는 그 이미지의 미러 경로는 media/full/8552a9e4d437d224.jpg입니다. 테스트 공유는 PNG 1개+JPG 1개, files만 전달(text/title 없음)으로 확인해야 합니다. 운영 HTTP 서버 역시 미러 파일의 올바른 Content-Type을 확인합니다. 이미지 누락 실패 차단 자체를 제거하여 결함을 숨기지 않습니다.


## 14. v2.5.4 AI 스킬·GitHub 스크린샷 정리

AI 스킬 탭은 기존 AI툴 자료와 하단 도구 모음에 연결됩니다. 인물 펼치기는 이름 바로 옆에 붙입니다. 접힌 카드 상단과 높이를 36px 줄여 PC314px/모바일304px로 표시합니다.

수집 후 미디어 미러 다음 enrich_tools.py --backfill을 실행합니다. 원문·인용의 이미지와 GitHub URL에서 후보를 모으고, Codex CLI의 읽기 전용 이미지 입력으로 분석합니다. 이미지에 URL이 없으면 제목/소유자 힌트로 저장소를 검색하고 실제 README와 포크 여부를 확인합니다. 모호한 경우 링크를 만들지 않습니다. 결과 data/ai-tools.json의 안정적인 글 ID 아래에 verified 제목·한국어 설명·구체적 분류·repo_url·근거·지문을 저장하며, 원문은 보존합니다. 프런트는 검증된 GitHub URL만 바로가기로 표시하고 설명도 검색에 포함합니다.

단순 progress의 완료 목록을 신뢰하지 않습니다. 현재 이미지+본문+URL+분석기 버전 지문과 일치하는 성공 캐시만 재사용합니다. 이미지 변경과 실패는 다시 처리합니다. 이미지 분석 자체는 내용 해시별 vision 캐시로 재사용합니다. 배치마다 tools/cache/progress 및 manifest.ai_tools 해시를 저장하여 타임아웃 이후에도 이어서 처리합니다. GitHub처럼 보이나 미확인인 자료와 일시 오류는 재시도 마커를 유지합니다. dry-run은 파일/마커를 쓰지 않습니다. 새 원문이 없어도 .retry-enrich가 후크를 다시 실행해야 합니다. 운영 워커 후크와 수동 백필을 같은 checkout에서 동시에 실행하지 않습니다.

검사 명령: python3 hooks/test_enrich_tools.py (15개: 실제 run_backfill의 캐시 무호출·이미지 변경·실패 다음 실행·dry-run 무쓰기 포함), node js/test_tool_metadata.mjs. 실제 검증 시 fresh URL 없는 이미지 분석/검색, 공유 이미지 하나를 여러 글에 연결, 모호한 후보 설명, 기존 자료 전체 처리 건수, 같은 입력의 모델 무호출을 기록합니다. 전체 검사와 실제 백필 완료를 구분합니다. fork와 복제 저장소가 여럿인 경우 공식 원본 근거를 추가 확인합니다.

예시: MatthewBerman 글2108245653843509415, 이미지86475eac4c71ca84.jpg → morluto/rea. 8552a9e4d437d224.jpg와 Lexmount 글2089327156274790890은 Moli Browser이며 REA가 아닙니다. 잘못된 자동 매칭은 원문을 수정하지 않고 근거/지문을 재검증하여 정리합니다.
